# m68k-os9-r68

`m68k-os9-r68` assembles Microware r68 sources (`.a`) with r68's own options, so that makefiles
and [m68k-os9-xcc](m68k-os9-xcc.md) can build them without Microware's assembler. Its objects are
ELF by default, or ROFs, and match Ultra C's `r68` byte for byte, or C 3.2's `r68` with
`-dialect=c32`. It runs [r68togas](r68togas.md), which translates the source for the GNU
assembler, then `gas`, then post-processes the object; the translation itself, and what it does
with each construct, is described in [r68togas.md](r68togas.md).

## Usage

    m68k-os9-r68 [options] <source>

Options are case-insensitive and may be given with or without `=` where r68 allows it, as in
both Microware assemblers: Ultra C's option set is a superset of C 3.2's in meaning and spelling,
so one parser takes both.

| Option | Meaning |
|---|---|
| `-o[=<path>]` | the output, under exactly the name given (no extension added: `-o=x` writes `x`); its content by `-obj=`. A bare `-o` writes `output.r`, as Ultra C's `r68` does. Without `-o` the source is only checked (and listed with `-l`) |
| `-a=<sym>[=<val>]` | define a symbol (1 without a value) |
| `-m<n>` | the CPU: 0 the 68000 (with the 68881 instructions, which r68 takes for any CPU), 1 the 68010, 2 the 68020 and the CPU32, 3 to 6 the 68030 to the 68060. With `-dialect=ucc` it also chooses the padding (see "Dialects" in [r68togas.md](r68togas.md)) |
| `-u[=]<dir>` | a directory to search for `use` files |
| `-b`, `-bt` | branch sizing: branches to the source's own labels sized by the assembler; `-bt` also branches to externals long |
| `-j` | long branches through a jump table: accepted with a note (the linker builds the jump table), and sizes branches as `-b`, which r68's `-j` implies |
| `-y` | with `-b` or `-bt`, on a 68020 or later: branches and PC-relative references to labels 32-bit; an error on a 68000 or 68010, as in r68 |
| `-r` | registers only with `%` (`%d0`) |
| `-p<n>` | accepted with a note |
| `-l`, `-s`, `-c`, `-g`, `-x` | listings (below) |
| `-n`, `-d<n>`, `-f` | accepted with a note |
| `-q` | quiet: no warnings |
| `-e` | accepted with a note |
| `-v` | version |
| `-z[=<file>]` | options from a file, one per line, as with our other front ends |
| `--<flag>` | the flag off again, as Ultra C's `r68` takes it (`--bt` after `-bt`): the last one given wins |

`-b`, `-bt`, `-j`, `-y`, `-p<n>`, `-r`, `-u` and `-z` are options of Ultra C's `r68` only. The
environment variable `M68K_OS9_ELF` is read as by the other front ends (`obj=` with an object
format: `elf`, `rof` or `ucc`; `gas` only on the command line). The output is never written over
the source, nor over another existing file a round trip through gastor68 would hit (see "No
overwriting" in [r68togas.md](r68togas.md)).

**`-obj=gas`** writes `r68togas`'s output instead of assembling it: one `gas` source that
`m68k-os9-as` assembles to the same object with the same messages, with the `-a` symbols as `set`
lines and the CPU as an `.arch` directive, so that it needs no options. Without `-o` it goes to
standard output. Only the post-processing below is missing from a plain `gas` run of it.

## What it runs

1. **`r68togas`** with `-a`, `-m` (always; `-m0` by default), `-u`, `-d` and the branch and
   register options.
2. **`m68k-elfos9-as`** with the CPU (`-m68000 -m68881` for `-m0`; `-m68040` and `-m68060` have
   the FPU) and the listing options; `-W` for `-q`.
3. **`objcopy`** on the object:
   - global and undefined symbols the translation renamed get their names back
     (`--redefine-sym`): those named like `gas`'s registers or with a dot (`NAME__r68`, the dot
     as `__dot__`), and those with `@` (`_at_`); so the object's names are those of Microware's
     objects and of `rof2elf`'s, and they link together;
   - the `.-LABEL` symbols of vsect labels, which `gas` leaves out, are added from the
     translation's notes (`--add-symbol`), and the notes' sections removed;
   - undefined symbols no relocation uses are removed: Microware's assemblers write no reference
     for them, and a link would take in a library member for one;
   - the sections' alignment is set to 2 where the dialect pads to 2 (`gas` makes 4), so that a
     link places the next psect right after.

Ultra C's `r68.exe` is not used; it is the reference for the tests.

## Listings

Not r68's exact layout, but each option's intent, through `gas`'s listing options:

| r68 | `gas` |
|---|---|
| `-l` | a listing to standard output (`-ahl`) |
| `-c` | with false conditionals (without `-c` they are left out) |
| `-x` | with macro expansions |
| `-s` | with the symbol table (also without `-l`) |
| `-g` | all code bytes (`--listing-cont-lines`) |

`-n` (no line numbers), `-d<n>` (page length) and `-f` (form feeds) have no `gas` counterpart and
are accepted with a note naming them.

C 3.2's `-C` "suppresses" the conditionals' listing and Ultra C's `-c` "prints" it, by their
usage texts; in behaviour they agree: C 3.2's listing leaves out false conditionals by default,
and `-c` lists them, as Ultra C's does.

## Microware compatibility

The objects are those of [r68togas](r68togas.md#microware-compatibility): compared byte for byte
with Microware's assemblers after `rof2elf`, on the cases in `tests/r68` and on a large set of
real r68 sources (more than a million lines in more than 3,300 files). A ROF written by
`m68k-os9-r68` and read back by `rof2elf` compares the same as its ELF object; ROFs linked by
C 3.2's `l68` give the same modules as its own assembler's.

Two things of Microware's drivers aren't reproduced:

- **`o68`:** C 3.2's `xcc` runs `.a` files through its optimizer `o68` before `r68` (`xcc -bp`:
  `o68 t3.a cm000354`, `r68 cm000354 -q -o=t3.r`). `m68k-os9-xcc` assembles what is written,
  without such a pass.
- **The ROF edition:** C 3.2's `r68` writes ROF edition 9, Ultra C's edition 9.1 (32-bit counts);
  `elf2rof` writes the edition the `-obj=` kind names (see [elf2rof.md](elf2rof.md)).

## Tests

The cases of `tests/r68` (see [r68togas.md](r68togas.md#tests)) run through `m68k-os9-r68`:
assembler cases with their expected values and, with `R68` set, compared with Ultra C's `r68`,
and script cases for the options and the front end's behaviour.
